# 系统 MCP 认证继承

系统设置 → 智能体设置 → 系统资源 → MCP 的认证配置支持：不发送认证、手动请求头、当前登录身份。配置仅作用于所选 MCP。

用户工作台默认开启“跟随系统配置”。关闭后，用户可设置个人认证方式及附加请求头；个人设置不会被后续系统修改覆盖。重新开启并保存会删除该用户的覆盖项，恢复跟随系统。

- 没有个人覆盖记录时，认证方式实时取系统默认；已有个人配置继续有效。
- 个人附加请求头与系统请求头合并，同名项（不区分大小写）优先使用个人值。
- “不发送认证”移除 Authorization，其余附加请求头不受影响。
- “当前登录身份”使用本次实际调用用户的 Bearer Token，不保存管理员或用户 Token；仍受既有运行时支持限制。
- 普通用户读取认证设置只返回自己的请求头，不回显系统保存的凭据。
- 系统默认认证方式只允许管理员或已有资源审核权限的用户修改。

## 发布与验证

发布后端前执行 `backend/migrations/041_system_mcp_auth_mode.sql`；旧数据默认保持手动认证，迁移可重复执行。已有的 `039_mcp_current_user_auth.sql` 仍为前置迁移。此次未执行目标库迁移或部署。

本地 28 项 MCP 后端测试、13 项相关前端测试及生产构建通过。真实组件配合模拟接口验证了系统认证方式显示与保存、个人默认继承、个人覆盖及恢复继承；未连接实际 MCP 服务做端到端调用。
