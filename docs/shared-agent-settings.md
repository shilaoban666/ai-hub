# 智能体设置与工作台设置

系统设置下保留品牌信息的「全局设置」，并提供两个独立入口：

- 智能体设置：Runtime 设置、积分策略、平台模型。Runtime 设置与积分策略共用全局版本；平台模型及费率继续通过模型管理接口保存。
- 工作台设置：默认助手、系统资源。默认助手的名称、头像、说明、身份提示词、默认模型使用独立的草稿和生效版本。

默认模型属于具体助手：工作台默认助手选择平台模型，自定义 Agent 可选择当前用户可见且兼容的已启用平台模型或个人模型。个人模型沿用原计费行为。

Web 工作台、自定义 Agent 和消息渠道在每次开始执行时，统一读取已生效的全局 Runtime 设置。每次运行记录配置版本、Runtime、推理强度、推理过程显示、轮次和超时的快照。草稿不生效，保存并生效不改变正在执行的任务。外部消息渠道继续隐藏推理过程。单用户并发限制在工作区执行租约入口统一执行。

身份提示词、智能体绑定资源、工作区、会话和凭据仍由原有作用域管理。系统资源仍只供工作台默认助手继承。

## 升级

更新后端前，可在 backend 目录执行：

```powershell
python migrations/052_split_workbench_settings.py --apply
```

迁移仅新增 `workbench_settings` 表，并复制旧设置的当前已发布默认助手及未发布草稿；重复执行不会覆盖已经拆分的设置。应用启动也会创建缺失表。在未迁移的安装中，读取默认助手兼容旧设置；首次通过新接口保存或发布时自动保留旧默认助手。

全局策略继续使用 `platform_agent_settings` 的 Runtime 与积分字段。新入口使用 `/api/admin/agent-settings` 和 `/api/admin/workbench-settings`；智能体设置用“保存并生效”生成并切换全局版本，仍可单独保存草稿。旧组合接口只保留历史配置读取，保存和发布返回 HTTP 410 并提示使用新入口，避免旧客户端写入后显示成功却未更新工作台。部署后重启 API 与消息渠道 Worker。

设置首次加载失败时禁止提交，页面提供重试；保存和发布后直接采用服务端返回的配置及版本。平台模型单独保存不会覆盖尚未保存的 Runtime 或积分修改。当前工作台默认模型不能直接停用或改为不兼容的协议，需要先更换默认模型并发布。
