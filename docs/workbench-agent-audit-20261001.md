## 当前必做项

### M1：运行期间上传与删除可能被整棵回写覆盖（P1）

- 位置：[文件上传](D:/git_repo/aihub/backend/agent_routes.py:2117)、[文件删除](D:/git_repo/aihub/backend/agent_routes.py:2219)、[native 回写](D:/git_repo/aihub/backend/sandbox/native.py:425)、[container 回写](D:/git_repo/aihub/backend/sandbox/container.py:201)。
- 上传/删除直接改持久化目录，没有参与运行使用的工作区互斥；运行从旧视图整棵替换文件目录。
- 临时目录调用真实 `ContainerSandbox.cleanup`：运行期间上传的文件在回写后不存在；运行期间删除的旧文件重新出现。native 的同步脚本采用同类整棵替换机制，风险同源，尚未在真实 Linux 上复现。
- 最小方向：文件变更与执行使用已有工作区互斥，忙时给明确反馈；避免增加文件版本合并系统。必须原子争抢，单独查询“有没有运行”不能消除竞态。
- 验收：运行与上传/删除并发时不会误报成功后丢失修改；两个 API 进程也遵循同一约束。

### M2：租约失效和重复取消没有封住文件写入生命周期（P1）

- 位置：[失联处理](D:/git_repo/aihub/backend/agent_service.py:1215)、[准备线程等待](D:/git_repo/aihub/backend/agent_service.py:1018)、[回写线程等待](D:/git_repo/aihub/backend/agent_service.py:1254)、[租约操作取消处理](D:/git_repo/aihub/backend/agent_execution_lease.py:46)。
- 租约失效后阻止会话结果保存，但 `finally` 仍调用会把旧视图写回持久化目录的 `cleanup`。模拟失联：运行状态为 `unknown`，仍观察到一次回写调用。这个复现证明调用路径，没有声称已复现真实多进程文件破坏。
- 准备/回写任务首次取消后直接等待未 shield 的线程任务；再次取消可以使等待者提前结束，而实际线程继续写。重复取消复现：执行任务已结束、准备线程未结束、cleanup 未调用。租约获取/释放也有同类等待模式，应一起检查。
- 最小方向：分清“回写”与“清理当前 run 的临时目录”，失去所有权禁止回写；沿用现有技能同步的等待方式，连续取消时也等写入结束再退出。回写提交与接管必须有一致的互斥边界，仅在复制前检查一次所有权不足以防止中途失效。
- 验收：旧持有者失联/被接管后不能覆盖新持有者文件；连续停止和关停不会在写入线程仍工作时释放名额。不能为此引入新的通用任务框架。

### M3：渠道动态模型回退漏取已有 Run（P2）

- 位置：[Run 加载条件](D:/git_repo/aihub/backend/agent_service.py:710)、[平台模型运行校验](D:/git_repo/aihub/backend/agent_service.py:882)。
- 现在允许专家没有固化的默认模型，运行时从当前模型目录回退；渠道使用 `manage_run_record=False`，却仍只有 `agent.default_model_id` 非空才加载已有 Run。
- 隔离复现：已有渠道 Run，专家默认模型为空、动态目录存在平台模型，结果失败并提示“平台模型运行缺少可审计的 Run 记录”。
- 最小方向：按渠道已有 run_id 加载记录，校验运行/用户/智能体归属，不依赖默认模型字段；不重建第二条 Run 或绕过平台计费。
- 验收：先建无模型专家、后新增平台模型，从渠道运行可以使用原 Run 正常计费；不存在或不匹配的 Run 被拒绝。

### M4：文件工作线程仍会隐式使用请求的 ORM Session（P2）

- 位置：[技能同步](D:/git_repo/aihub/backend/agent_routes.py:738)、[运行准备](D:/git_repo/aihub/backend/agent_service.py:1009)、[native 同步读取字段](D:/git_repo/aihub/backend/sandbox/native.py:602)。
- Session 默认在 commit 后使字段过期，把 ORM Agent/Workspace/Model 直接交给文件线程并不能保证线程只做文件操作；读取字段会触发重新查询。
- 使用真实 SQLite ORM Session，并记录 SQL 执行线程：技能同步的工作线程触发 8 次 SQL 查询。现有线程归属测试用 SimpleNamespace/MagicMock，无法覆盖过期字段。没有把这一观察描述成已经发生的 MySQL 数据损坏。
- 最小方向：请求/执行所属线程先读取所需字段与资源，给文件线程传普通值快照；不全局关闭 ORM 过期行为，也不把整个 Session 搬入线程。检查技能同步和运行准备两条路径。
- 验收：真实 ORM、commit 后的测试场景中，文件线程 SQL 查询数为 0；配置仍按每次执行的有效状态解析。

### Native 取消实机发现与修复（2026-10-02）
