# 对话刷新恢复与 Redis 配置

Web 对话由独立后台任务执行。刷新、关闭页面和网络断开只停止订阅，不取消执行；只有主动停止会请求取消。历史列表返回 `active_run_id` 并显示 loading，打开后恢复已有输出并续接增量。

停止后会保存本轮已经收到的回复、用量和运行关联。停止接口、后台轮询等重复发出的取消信号不会中断运行时停止、工作区清理及最终消息保存；这些步骤仍检查运行租约，失去租约的执行端不会写回结果。消息写入及压缩重试均失败时，本轮返回 `assistant_message_save_failed` 并显示保存失败提示，不再静默标记成功。本修复不需要数据库迁移，也不会自动补回以前没有保存的回复；服务进程被强制终止仍可能导致内存中尚未保存的输出丢失。

工具结果中的 `s_html` / `html` 预览会在截断诊断文本前完整保存到工具结果的 `resultHtml` 字段，历史加载和已完成任务的快照回放均读取该字段，避免长 JSON 被截断后预览消失。仍受整条消息的字节上限约束，超过上限会显示压缩提示。先部署兼容此字段的前端，再部署后端，或同步发布；旧消息中已经被截断的 HTML 无法通过此修复补回。

## 部署配置

后端安装更新后的 `backend/requirements.txt`，提供 Redis 5+（支持 Streams 和 Lua）。可以复用已有实例，不需要为每个 API 进程单独部署 Redis。所有 API 实例必须连接同一 Redis、同一逻辑数据库并使用相同前缀；开发、测试、生产使用不同前缀。

```dotenv
REDIS_HOST=172.26.6.160
REDIS_PORT=6380
REDIS_PASSWORD=
```

后端读取上述三个配置项，不再读取 `AIHUB_REDIS_URL`。密码留空表示不认证；有密码时直接填写原值，无需 URL 编码。默认使用 Redis 的 0 号数据库，键前缀为 `aihub:chat:`，可通过可选配置 `AIHUB_REDIS_PREFIX` 按环境调整。地址和凭据由后端 `.env`、部署环境或 Secret 提供，前端不配置、不接触 Redis。当前使用普通 TCP 连接单节点或托管主端点，不支持直接配置 Sentinel/Redis Cluster 拓扑。

启动时检查临时键的读写能力；配置缺失或 Redis 不可用时，其他平台功能仍可启动，新 Web 对话在创建任务前返回明确的 503。检查不输出连接地址或密码。Redis 账号需要允许对应前缀下的 Lua、Hash、Streams、过期和删除命令，不能只授予 PING。

## 存储与恢复

- 新 Web 任务不再向 `agent_run_events` 写入数据，也不依靠每 250ms 查 MySQL 来吐字。既有 SQL 表只用于旧任务兼容和分批清理。
- 执行端把约 50ms 内的输出合并成一批写入 Redis Streams；订阅端阻塞等候新数据。正常吐字不需要等完整快照。
- 完整快照通常每 5 秒更新一次，开始、授权、结束等控制事件立即更新；积累达到 256 批或 256KiB 增量时提前合并。快照合并连续文本/思考并累计 usage，保留工具调用顺序，不保留逐 token 历史。
- 保存快照和裁剪旧增量通过同一 Lua 操作完成，读取快照和增量也具有原子性。过旧的游标自动恢复到最新完整快照，再接增量；重连不会重新提交问题。增量保留量有界，完整输出的大小仍随本轮实际内容增长。
- 快照和流的 TTL 均为 10 分钟，运行期间随发布刷新，无输出时每 30 秒续期；终态后约 10 分钟自动过期。最终消息、任务状态、用量和积分仍保存在 MySQL，缓存到期后从永久历史恢复。
- Redis 运行中暂时故障不会取消模型任务。执行端继续在内存中合并完整输出，最多每 5 秒尝试恢复（关键状态可提前重试）；恢复时发布完整快照补齐缺口。终态缓存写入失败时，读端通过永久历史恢复。任一缓存键被淘汰时，也由执行端重新补全。
- MySQL 仍有任务控制、租约心跳和授权决策查询；本次迁移的是输出通道，并非移除全部运行期 SQL。读端最多每 15 秒核对一次终态/授权，兼容旧执行端和缓存缺失；不会随 token 数量增加查询。授权请求送达时额外校验，另一页面处理后最迟下一次核对移除。

每个活跃 SSE 订阅占用一个 Redis 阻塞连接，需按并发量配置 Redis 内存和连接容量。缓存到期只回收临时输出，不清除永久对话和计费记录。Redis 不承担模型任务调度；服务进程退出或宕机后的模型续跑仍受原有异常运行恢复机制约束。

## 升级与旧数据

先部署支持 `run_snapshot` 和 `run_delta` 的前端，再部署配置好 Redis 的后端，或同步发布。`043_agent_run_events.sql` 保留用于兼容旧版本：旧事件及单行 SQL 快照仍可读取，已结束超过 10 分钟的数据自动清理；每次事务最多 1,000 条，每轮最多 10 批，每分钟执行一轮。运行中和待核查的记录不清理，不做全表删除。

## 本地验证

测试依赖见 `backend/requirements-test-stream.txt`。后端使用独立 SQLite 和 fakeredis（实际执行 Lua 脚本），覆盖断开后继续执行、主动停止、跨读端恢复、裁剪与淘汰、缓存故障后永久历史回退、授权过滤和 SQL 清理。前端测试覆盖快照替换与增量去重；`frontend/browser-tests/chat-refresh.mjs` 在真实浏览器中用模拟接口验证刷新、历史 loading、续接和停止。

上述本地测试不代表已连通部署环境的 Redis，也不替代真实网关、模型和多实例环境联调。

## 错误来源与趣点展示

失败提示保留可展开的原始错误详情，并标注模型上游、AIHub、运行环境或模型连接；证据不足时显示“来源未确认”。上游 HTTP 错误保留状态码、错误类型、消息和可取得的 request ID，流式响应中的网络错误转成明确的错误事件。详情会脱敏并随助手消息保存，刷新历史和缓存到期后的回放仍可查看；旧记录中已经丢弃的原始错误无法补回。

Claude 的 `[claude-code:unrecognized_model]` 是模型目录诊断标记，不能单独用于判断模型不可用。运行超时、模型请求超时和连接中断分别显示对应提示。网关只对连接建立失败进行有限重试，不在读超时后自动重放已被上游接受的生成请求。

个人及专家对话均展示服务端记录的趣点消耗。实时计费任务即使仍待对账，也返回已经扣除的金额；该金额可能随迟到的用量回报更新。未结算的旧预留计费记录继续等待结算，不根据 Token 数推算金额。
